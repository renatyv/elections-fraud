## 2. Карта эндпоинтов (проверены 10.10.2026, всё живое)

База: `https://resultados.tse.jus.br/oficial/ele2026/…` (ele2026 — цикл выборов 2026).

| Файл | Шаблон | Содержимое |
|---|---|---|
| Индекс выборов | `oficial/comum/config/ele-c.json` | Все плебисциты/выборы: коды, туры, должности, штаты. **Источник кодов — скрипт читает его сам** |
| Результаты (unificado) | `ele2026/{ele}/dados/{uf}/{uf}-c{cargo}-e{ele}-u.json` | Голоса по кандидатам + участки + электорат; `{uf}{mun}` — уровень муниципалитета |
| Прогресс подсчёта | `ele2026/{ele}/dados/br/br-e{ele}-ab.json` | % обработанных участков и электората по каждому штату |
| Конфиг муниципалитетов | `ele2026/{ele}/config/mun-e{ele}-cm.json` | Список муниципалитетов по штатам (коды TSE) |
| Избранные | `…/{uf}-c{cargo}-e{ele}-e.json` | Победители (после финиша) |

**Коды выборов 2026** (из ele-c.json): президент — **6257** (1-й тур) / **6258** (2-й тур, 25.10); губернаторы и законодательные — 6259 / 6260; консельеры DF — 6261.
**Коды должностей (cargo):** 1 — Presidente, 3 — Governador, 5 — Senador, 6 — Dep. Federal, 7 — Dep. Estadual, 8 — Dep. Distrital.

Ключевые поля `u.json`: `dg/hg/idg` — дата/время/порядковый номер генерации файла (по нему делается дедупликация); `s` — участки (total/aporado/%); `e` — электорат; `v` — голоса (валидные/бланко/нулевые); `carg[].agr[].par[].cand[]` — кандидаты: имя урны, партия, коалиция, `vap` (голоса), `pvapn` (% валидных, запятая как разделитель), `e` (избран), `st` (статус).

## 3. Скрипты (уже протестированы на реальных данных)

```
brazil-oct-2026/
├── scripts/
│   ├── tse_scrape.py        # скрейпер: uv-скрипт (PEP 723), httpx[http2] + rich
│   └── run_tse_scrape.sh    # обёртка разового прохода (для cron/launchd), зовёт uv
├── launchd/com.elections.brazil2026.plist   # агент macOS: каждые 15 минут
└── data/                    # создаётся скриптом
    ├── snapshots/{ele}/…json  # сырые снапшоты (пишутся только при изменении idg)
    ├── timeline.csv           # временной ряд по кандидатам
    ├── progress_by_uf.csv     # % подсчёта по штатам
    ├── latest.json            # компактная сводка последнего прохода
    └── scraper.log
```

Зависимости (`httpx[http2]`, `rich`) объявлены в PEP 723-заголовке `tse_scrape.py` — `uv run` сам ставит их в кэшируемое окружение при первом запуске, отдельный venv или pip не нужны. Нужен только [uv](https://docs.astral.sh/uv/) (уже установлен: `~/.local/bin/uv`). Выигрыш от httpx: один клиент с пулом соединений и HTTP/2 на все циклы (28 штатов за проход летят по одному соединению), таймауты/ретраи из коробки; rich рисует сводную таблицу кандидатов в консоль после каждого прохода.

### Запуск

```bash
# вручную, цикл каждые 15 минут (по умолчанию 2-й тур президентских, вся страна):
uv run scripts/tse_scrape.py --loop

# разовый проход (то, что дёргает cron/launchd):
uv run scripts/tse_scrape.py --once

# полезные варианты:
uv run scripts/tse_scrape.py --loop --uf all                  # + все 27 штатов
uv run scripts/tse_scrape.py --loop --turno 1                 # 1-й тур (финал)
uv run scripts/tse_scrape.py --loop --election 6260 --cargo 3 --uf all   # 2-е туры губернаторов
```

### Автозапуск каждые 15 минут (macOS)

```bash
cp launchd/com.elections.brazil2026.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.elections.brazil2026.plist
# снять: launchctl unload ~/Library/LaunchAgents/com.elections.brazil2026.plist
```

Альтернатива — cron (`crontab -e`):

```
*/15 * * * * "<путь>/brazil-oct-2026/scripts/run_tse_scrape.sh" >> "<путь>/brazil-oct-2026/data/cron.log" 2>&1
```

### Поведение

- Каждый проход перечитывает `ele-c.json` → сам находит код 2-го тура (не сломается, если TSE сменит коды).
- Скачивает `u.json` (страна, при `--uf all` ещё и штаты) и `ab.json` через один httpx-клиент (HTTP/2, пул соединений живёт между циклами); 404 до старта подсчёта считается нормой и просто логируется.
- Снапшот и строка в CSV пишутся **только когда изменился `idg`** — на «тихих» проходах только heartbeat в лог. Есть блокировка от параллельных запусков, ретраи, пауза 0,5 с между запросами (вежливо к CDN TSE).
- `timeline.csv` — одна строка = кандидат в момент среза: время, выборы, штат, партия/коалиция, голоса, %, % обработанных участков, электорат и т.д.
- В консоль после прохода печатается rich-таблица топ-8 кандидатов с прогрессом подсчёта (в лог она не пишется, там простой текст).

## 4. Хронология 25.10.2026

- Участки закрываются в 17:00 по Бразилиа (UTC−3) = **20:00 UTC = 23:00 МСК**; в части штатов (западные зоны) — на 1–2 часа раньше по местному.
- Первые тотализированные сводки — обычно в пределах ~30–60 мин после закрытия; полный подсчёт ~155 млн голосов исторически занимает 2–3 часа.
- Рекомендуемое окно интенсивного опроса: 25.10 20:00 — 26.10 02:00 UTC. Интервал 15 минут даёт ~10–15 содержательных срезов за ночь; накопление данных — единицы МБ.

## 5. Ограничения и заметки

- Числа в JSON — с запятой-разделителем (`47,03`); в CSV сохранены как есть, числовой процент — в `pct_validos_num`.
- У TSE есть тестовые окружения (`resultados-hmg`, `simulado`) — скрипт работает только с `oficial`.
- Bulk-выгрузки для пост-анализа (участковые протоколы BU и др.) появляются на dadosabertos.tse.jus.br спустя дни — для проверки цифр в ночь выборов они недоступны, скрейпить реалтайм-JSON — единственный вариант.
- API публичное и не требует ключа; при 15-минутном интервале и ~30 запросах за проход нагрузка пренебрежима.
